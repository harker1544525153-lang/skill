# 三类产品文档（架构图 / 流程图 / 原型设计）Word 输出格式规范（通用版）

> 本文为**通用格式规范（Skill）**，规定「产品架构图文档」「业务流程图文档」「产品原型设计文档」三类 Word 交付物的统一输出要求。
> **生成管线**：`Source/md/{产品名}{文档类型}.md`（Markdown 源稿，唯一真源）→ `Source/md_to_docx_final.py` → `Source/{产品名}{文档类型}.docx`；md 中的 ```` ```mermaid ```` 代码块经 mermaid-cli 渲染为 `Source/picture/figure_{docIndex:02d}_{seq:03d}.png` 并插入文档。
> **示例与通用**：下文三类文档的**章节骨架以永达SOC 为示例**，仅用于说明格式；真实项目的骨架（模块/业务域/页面/角色）须按项目实际推导，但**第三节的格式基线对所有项目强制一致**。
> 源样例：永达 SOC 三份同名文档及其 `Source/md/*.md`、`Source/picture/*.png`、生成脚本 `Source/md_to_docx_final.py`。

---

## 一、生成管线与目录约定（通用）

| 产物 | 路径 | 说明 |
|------|------|------|
| Markdown 源稿 | `Source/md/{产品名}{文档类型}.md` | 文档唯一真源；改文档先改 md 再跑脚本 |
| 配图（渲染后） | `Source/picture/figure_{docIndex:02d}_{seq:03d}.png` | 由 md 内 mermaid 渲染；`docIndex`=该文档在生成列表中的序号（01/02/03/04…），`seq`=文档内 mermaid 块顺序 001 起 |
| 配图源码 | `Source/picture/figure_{docIndex:02d}_{seq:03d}.mmd` | mermaid 原生源码，便于改图重渲（脚本渲染后默认删除，可保留） |
| Word 交付 | `Source/{产品名}{文档类型}.docx` | 最终交付；与 md 同名 |
| 生成脚本 | `Source/md_to_docx_final.py` | 统一生成四类文档（整合版PRD / 原型设计 / 业务流程图 / 架构图） |
| 根目录说明 | `Source/README.md` | `Source/` 目录结构与归档模板，可跨项目复用 |

> **复用提示**：脚本中的 `DOC_INFO`（产品名/版本/日期/作者/部门/密级）、`UPDATE_HISTORY`（更新记录）、`md_files`（文档列表与顺序）为**项目相关参数**，换项目须重指；格式相关函数 `set_doc_style / add_title_page / add_update_history / add_table_of_contents / add_doc_table / add_image / add_page_number` 为**通用能力**，可直接复用。

---

## 二、正文结构三段式（脚本强制，三类一致）

每个文档由脚本统一拼出以下三段，再接 md 正文：

1. **标题页**（`add_title_page`）：居中。主标题 22pt 加粗 `#003366`；下方产品名；再下「版本 / 日期 / 作者 / 部门 / 密级」（标签加粗 + 值）；底部部门名；后插入分页。
2. **更新记录**（`add_update_history`）：标题「更新记录」18pt 加粗 `#003366` 居中；表格 `版本 | 日期 | 作者 | 修改内容`（`Table Grid`，表头加粗白字填充 `#4472C4` 居中，数据行居中行距 1.0）；后接正文。
3. **目录**（`add_table_of_contents`）：标题「目录」18pt 加粗 `#003366` 居中；插入 `TOC` 域（`TOC \o "1-3" \h \z \u`）；后分页。
4. **正文**（解析 md）：见第三节 / 第四至六节。

## 三、Word 统一格式基线（脚本强制，跨项目不可改）

| 项目 | 规范（来自脚本） |
|------|------|
| 页面 | A4（21×29.7cm），四边页边距 2.54cm |
| 正文字体 | 微软雅黑 10.5pt；行距 1.5；段后 6pt |
| 标题字体 | 微软雅黑、加粗、颜色 `#003366`（RGB 0,51,102） |
| 标题字号 | H1=16pt / H2=14pt / H3=12pt / H4=11pt（md 中 `#####`、`######` 均映射为 H4） |
| 每个一级标题 | `# `（H1）前自动插入分页符（每章新页） |
| 表格 | `Table Grid` 边框、整体居中；表头：加粗、白字、填充 `#4472C4`、居中；数据行居中、行距 1.0、微软雅黑 |
| 配图 | mermaid 块渲染（`mmdc -t default -w 2400 -H 1600 -s 2`）；按页宽等比缩放（最大宽 = 21−2×2.54 = 15.92cm，最大高 ≈ 21.62cm，缩放比 ≤1）；图下居中加粗图标题「图 N 架构图/流程图」，**N 为本文档内连续递增**（每文档从 1 起算） |
| 图文件命名 | `figure_{docIndex:02d}_{seq:03d}.png`（docIndex=生成列表序号，seq=文档内 mermaid 顺序） |
| 页脚 | 居中「第 N 页，共 M 页」（`PAGE` / `NUMPAGES` 域，自动更新） |
| 列表 | `- ` / `* ` → 项目符号；`1. ` → 编号；`**文本**` 转原生加粗 run（Word 内不保留 `**`） |
| 分隔线 | `---` 忽略不渲染 |
| 加粗/编号 | Word 中使用原生 `run.bold` 等格式，正文英文术语按项目约定处理 |

## 四、文档一：产品架构图文档（骨架示例，按实际项目生成）

> 骨架依据：从项目的**实际技术分层 / 功能域 / 技术栈 / 数据流 / 部署拓扑**推导；下列章节为永达SOC 示例，模块名称按真实架构替换，五大架构图可裁剪。

```
{产品名}产品架构图文档（md 首行 # 标题；正文前经标题页+更新记录+目录）
├─ ## 文档信息                         ← 表：项目 | 内容（文档名称/版本号/编制日期/编制人/适用范围）
├─ ## 1. 文档概述
│   ├─ ### 1.1 文档目的
│   └─ ### 1.2 架构说明               ← 分层简述（项目符号）
├─ ## 2. 系统架构图
│   ├─ ### 2.1 系统架构图             ← mermaid 图 → 图 N 架构图/流程图
│   └─ ### 2.2 系统架构说明
│       ├─ #### 2.2.1 展示层          ← 表：组件 | 说明
│       ├─ #### 2.2.2 应用层
│       ├─ #### 2.2.3 服务层
│       ├─ #### 2.2.4 数据层
│       └─ #### 2.2.5 基础设施层
├─ ## 3. 功能架构图                    ← 3.1 图 / 3.2 说明（表：模块|子模块数量|功能需求数量）
├─ ## 4. 技术架构图                    ← 4.1 图 / 4.2 说明（前端/后端/数据库/基础设施 技术栈，表：技术|版本|用途）
├─ ## 5. 数据架构图                    ← 5.1 图 / 5.2 说明（来源/采集/处理/存储/应用，列随语义：来源|数据类型|采集方式 等）
└─ ## 6. 部署架构图                    ← 6.1 图 / 6.2 说明（外部网络/边界层/应用层/数据层/基础设施层，表：组件|说明）
```

**配图要求**：每类架构图至少 1 张（示例 5 张：系统/功能/技术/数据/部署）；图下紧跟「图 N 架构图/流程图」；分层说明统一「组件 | 说明」两列表，技术栈统一「技术 | 版本 | 用途」三列表。

## 五、文档二：业务流程图文档（骨架示例，按实际项目生成）

> 骨架依据：从项目的**实际业务流程 / 角色 / 审批链 / 权限分支**推导业务域清单；下列域为永达SOC 示例，业务域按真实流程增删，每个域必须带角色泳道或权限分支。

```
{产品名}产品业务流程图文档
├─ ## 文档信息                        ← 表：项目 | 内容
├─ ## 1. 文档概述
│   ├─ ### 1.1 文档目的
│   ├─ ### 1.2 流程图说明             ← 表：符号 | 含义
│   └─ ### 1.3 角色权限说明           ← 表：角色 | 权限范围 | 核心职责
├─ ## 2. 整体业务流程图
│   ├─ ### 2.1 带角色泳道的整体业务流程图   ← mermaid 图 → 图 N
│   └─ ### 2.2 整体业务流程说明              ← 表：节点 | 说明
├─ ## 3~11. 各业务域流程图（结构相同，域按实际项目定）
│   示例域：用户登录与权限校验 / 告警处理 / 资产管理 / 用户权限管理 / 策略管理(带审批) / 漏洞管理 / 等保合规检查 / SOAR自动化响应 / 数据流向图
│   每个业务域：
│     ├─ ### X.1 {业务域}流程        ← mermaid 图（带角色泳道/权限分支/审批节点）+ 图标题
│     └─ ### X.2 {业务域}流程说明    ← 表：节点 | 说明  +  角色权限矩阵 表
└─ ## 12. 图例与备注
    ├─ ### 12.1 流程图符号图例        ← 表：符号 | 名称 | 用途 | 示例
    ├─ ### 12.2 角色权限矩阵          ← 表：模块 × 角色（多列矩阵）
    ├─ ### 12.3 流程异常回流说明      ← 表：流程名称 | 异常场景 | 回流处理
    └─ ### 12.4 流程编号规则          ← 表：前缀 | 含义 | 示例
```

**配图要求**：整体图 + 每个业务域各 1 张，编号连续；每张流程图必须带角色泳道或权限分支标注；图例符号须与 12.1 一致。

## 六、文档三：产品原型设计文档（骨架示例，按实际项目生成）

> 骨架依据：从项目的**实际模块清单 / 页面 / 角色权限矩阵 / 术语 / 状态机**推导；下列章节为永达SOC 示例，分模块章节（第 7 章）须按真实模块递进编号，严禁层级编号回退。

```
{产品名}产品原型设计文档
├─ ## 文档信息
├─ ## 1. 文档元数据                    ← 1.1 文档标识(字段|值) / 1.2 文档目的 / 1.3 设计目标 / 1.4 读者对象(角色|阅读目的)
├─ ## 2. 迭代范围                     ← 版本信息 / 覆盖模块(模块|子模块|迭代状态|说明) / 新增内容
├─ ## 3. 业务流程                      ← 核心业务/告警处置/设备管理/漏洞管理/等保合规 流程图
├─ ## 4. 角色权限                     ← 角色定义(角色名称|角色标识|角色描述|默认首页) / 角色权限矩阵(模块×角色) / 权限隔离规则(隔离类型|规则|视觉表现)
├─ ## 5. 术语字典                     ← 产品术语(术语|英文|定义|使用场景) / 技术术语 / 界面术语
├─ ## 6. 全局通用UI规范
│   ├─ ### 6.1 视觉风格（色彩体系 颜色类型|色值|用途 / 字体规范 / 图标规范）
│   ├─ ### 6.2 全局通用组件（导航/筛选栏/数据表格/弹窗/图表/标签状态/卡片/上传/进度/权限置灰，每组件 区域|组件|说明）
│   ├─ ### 6.3 全局通用交互需求（数据下钻/批量操作/消息通知/导出打印/表单校验/自动回填/超时加载/空状态/拓扑画布/大屏交互 等）
│   └─ ### 6.4 适配需求（适配场景|标准）
├─ ## 7. 分模块原型设计（按真实模块逐页，每页 区域|组件|说明 + 配图；7.1~7.N 严格递进）
│   示例模块：大屏仪表台 / 资产管理 / 安全管理 / 脆弱性管理 / 组织与供应链 / 项目管理 / 应急响应与处置 / 知识库与补丁库 / 系统管理 / 登录门户个人中心
├─ ## 8. 数据状态流转                 ← 告警/设备/漏洞/工单 状态流转（状态|触发条件|下一状态|说明）
├─ ## 9. 接口联动                     ← 跨模块(联动场景|触发模块|目标模块|联动内容) / 外部系统(系统|接口类型|联动内容) / 数据同步(同步类型|同步方式|频率|说明)
├─ ## 10. 异常兼容                    ← 网络/数据/权限/操作 异常（异常场景|处理方式|视觉表现）
├─ ## 11. 文案埋点                    ← 埋点规范(埋点类型|命名规则|示例) / 事件结构(字段|类型|说明) / 必埋点页面(模块|页面|必埋点事件)
├─ ## 12. 配套附件                    ← 设计资源/原型文件/关联文档 清单
├─ ## 修订记录                        ← 表：版本 | 日期 | 修订内容 | 编制人 | 审核人
├─ ## 验收标准                        ← 15.1 UI交付输出物要求（输出物|说明）
```

**配图与表格**：分模块原型每页含「区域 | 组件 | 说明」三列表 + 该页面原型配图（图 N 连续）；术语/色彩/状态流转/埋点按上列结构建表。

## 七、按实际项目生成骨架的通用方法

| 文档类型 | 骨架推导依据 | 可变项 | 固定项（基线） |
|----------|--------------|--------|----------------|
| 架构图文档 | 实际技术分层、功能域、技术栈、数据流、部署拓扑 | 五大图是否齐全、分层命名 | 第三节格式基线、图标题「图 N 架构图/流程图」 |
| 流程图文档 | 实际业务流程、角色、审批链、权限分支 | 业务域数量与名称、泳道角色 | 第三节基线、每域「图+节点说明+角色权限矩阵」、图例与编号规则章节 |
| 原型文档 | 实际模块清单、页面、角色权限矩阵、术语、状态机 | 分模块章节、页面数、交互项 | 第三节基线、1~12 章语义框架、修订记录表头五列 |

**原则**：章节号连续无跳号；分模块章节（原型第 7 章）严格递进；新增业务列须在同类表内一致；角色权限矩阵行固定为角色、列按权限维度展开。

## 八、跨项目复用要点

1. **唯一真源**：改 Word 先改 `Source/md/*.md`，再跑 `Source/md_to_docx_final.py`；md 文件即格式范本，可直接拷贝为新项目模板。
2. **占位符**：`{产品名}`、`{文档类型}`、`{版本}`、`{docIndex}`、`{模块/业务域/页面}`、`{角色}` 替换为目标项目实际值；骨架可变，格式基线不可变。
3. **三段式固定**：标题页（版本/日期/作者/部门/密级）+ 更新记录表（版本｜日期｜作者｜修改内容）+ 目录，对所有文档一致；正文「文档信息」节为 `项目 | 内容` 表。
4. **配图连续编号**：图标题「图 N 架构图/流程图」的 N 在**单个文档内**从 1 连续；图文件 `figure_{docIndex:02d}_{seq:03d}.png` 前缀由生成列表序号决定。
5. **脚本参数化**：换项目重指 `DOC_INFO` / `UPDATE_HISTORY` / `md_files`；格式函数直接复用。
